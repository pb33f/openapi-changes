# Native JSON Schema comparisons

Give `summary`, `report`, `markdown-report`, `html-report`, and `console` a JSON Schema as their comparison root. Ship a working single-root comparison through all five commands first. Then give those same commands a collection root named **Schemas**. A change to a shared definition belongs to its defining resource. The graph shows each place that uses it.

This plan incorporates the [plan-crush findings](2026-11-25-json-schema-comparisons-plan-crush.md). The CLI baseline is `f9f73e7`. It selects Doctor `v0.0.88`, libopenapi `db27aae9`, libasyncapi `v0.0.7`, and Cowboy Components `0.16.0`. [Go dependencies](../go.mod) and [report UI dependencies](../html-report/ui/package.json)

## Milestone 1. One schema root on each side

```sh
openapi-changes summary before/customer.schema.json after/customer.schema.json
openapi-changes report --schema --reproducible before.json after.json
openapi-changes console --schema HEAD~1:schemas/customer.json HEAD:schemas/customer.json
```

A supported `$schema` declaration selects JSON Schema automatically. Use `--schema` for an unmarked object, `{}`, or a boolean. The initial dialect is Draft 2020-12. Under explicit schema mode, use that dialect when the declaration is absent. Name the file, side, and declared URI when a dialect is unsupported. Accept JSON and its JSON-compatible YAML representation. Keep API version markers on the existing OpenAPI and AsyncAPI routes. Reject conflicting kinds, invalid roots, malformed syntax, and duplicate mapping keys. A `$schema` pointing to an application's validation schema is insufficient for automatic selection. [JSON Schema roots and dialects](https://json-schema.org/draft/2020-12/json-schema-core#section-8.1.1)

### Comparison and reporting contract

- **Compatibility.** The original schema is the published contract. Mark a change as breaking when it can reject previously accepted data or remove a published address. For the default policy, `true` to `false` breaks, `false` to `true` widens, adding a required field breaks, and raising `minLength` on a plain string breaks. Lowering it widens. Apply these directional rules only in contexts where they hold. Negation can reverse the effect, and `oneOf` can make it ambiguous. Use conservative classification where direction cannot be established. Apply an explicitly supplied `schemaRules` property override before defaults. Keep the original override distinct from the merged defaults so an explicit `true` takes effect on a widening edit.
- **Published definitions.** Compare `$defs` keys and their contents even when the root never refers to them. Include `$id` and static `$anchor` edits. An address removal or rename breaks references to the old address. A `$defs` entry is a named subschema and can introduce a resource with its own `$id`. Resolve `$ref` siblings and nested bases by the declared dialect. Test `$dynamicRef` with `$dynamicAnchor` against its evaluation scope. Give a specific unsupported-feature error for a case the resolver cannot represent. Exercise `prefixItems` order and metadata-only edits. A description edit is visible and nonbreaking by default. Diagnose unresolved references and unsupported required vocabularies before returning an unchanged result. [JSON Schema resource and reference rules](https://json-schema.org/draft/2020-12/json-schema-core#section-8.2)
- **Machine identity.** Use `specification.kind = "jsonschema"` and the effective dialect URI in `originalVersion` and `modifiedVersion`. On schema changes, carry an additive `schemaResource` key alongside the native resource-relative JSONPath. For a required-list addition, `path` is `$.required`, `property` is `required`, and `new` is the member name. Whole-root changes use `$`. Use the canonical `$id` when it is independent of the checkout. Express IDs derived from a snapshot file base in that snapshot's relative namespace. Use the normalized source-relative name for an anonymous resource. Match directly supplied roots by argument position even if their names differ. Choose the modified resource key if its owner survives, and the original key if the resource is removed. Keep `rawPath` for a rewritten engine path.
- **Counts and hashes.** Include the resource key in the existing semantic edit identity used by Doctor and the CLI. Pass each original change through flat JSON. Derive human counts from the existing deduplicator. Use the same schema identity fields for grouping and deterministic sorting. For schema `changeHash`, hash an unambiguous encoding of resource, native path, property, change type, and old/new values, including structured values and reference targets. Coordinates serve navigation. Keep the existing hash algorithm for API formats. Test the custom `Change.MarshalJSON` and the flattened output. [CLI deduplication](../internal/changecounts/deduplicate.go) and [flat report hash](../model/report.go)
- **Sources and history.** One root may refer to another file. Use each side's existing file, URL, or revision configuration and its remote-reference policy. For Git and GitHub, a sibling comes from the same revision as its root. Equal root bytes permit a shortcut only after reachable dependencies are accounted for. Reuse the bounded history window and console cache. Preserve public `ParseSpecification` and `HistoryWindow.Acquire` callers with thin adapters over the native input path. Keep distinct outcomes for an unchanged pair, a first revision, a failed direct comparison, and mixed history with `metaData.partial` and `skippedCommits`. Direct reports omit synthetic commit details. [Source loading](../cmd/left_right_sources.go) and [history ownership](../model/history_source.go)
- **Source navigation.** Use existing root buffers for a self-contained pair. For multi-file inputs add an optional source table to each report item, keyed by side and source. Store each required file once per side. Optional `context.originalDocument` and `context.modifiedDocument` select the file for the existing line and column on that side. Keep `context.document` for existing consumers. Key line maps by side and file. Use the original for removals and modified for additions. A modification can display both, including after a move. The console uses the same lookup and its existing cache. HTML must work offline. Use the loader's sanitized display locations in exported sources. Keep the raw document tree and generate the explorer view from a copy. [HTML payload and explorer](../html-report/generator.go) and [terminal source selection](../tui/v2/diff.go)

Scope standalone defaults and `schemaRules` to the schema comparison. Reuse the CLI's existing `breakingrules.Acquire` guard for any reads of libopenapi's active policy and release it on error. A legacy unscoped rule file receives the existing format-specific diagnostic. Test custom rules followed by a default run and concurrent runs with opposing rules. [Rules configuration](../cmd/comparison_rules.go) and [policy guard](../internal/breakingrules/config.go)

## Milestone 2. Collections with shared references

```sh
openapi-changes html-report --schema --report-file changes.html ./before/schemas ./after/schemas
```

Two explicitly supplied local directories are snapshots and produce one comparison item. Recursively enumerate regular `.json`, `.yaml`, and `.yml` files in stable relative-path order. These directories are curated schema sets, so unmarked schemas and arbitrary filenames work. Skip Git metadata and directory symlinks. A single `$defs` bundle continues to use the file route. Named-file history retains its existing `repo file` and GitHub file-URL syntax.

Traverse schema-bearing positions, including embedded `$id` resources. Treat `examples`, `default`, and `const` values as instance data. Surface an error with both origins for duplicate resolved IDs in schema mode. Resolve local members by ID before any permitted external lookup. Compare each matched pair of authored definitions once. **Matching.** First match equal resolved `$id` values. Project file-derived URIs under each snapshot onto its relative namespace for identity, output, and hashing, so different checkout directories compare consistently. Resolve actual references against their real base on each side. Pair remaining resources at the same unambiguous relative file and embedded pointer. This exposes an ID rename at the same location as an ID change. A pure move with a stable absolute ID and equivalent references retains identity and adds zero semantic edits. Remaining original and modified members are removals and additions. Order output by resource and local path. Fail a direct snapshot pair clearly on an ambiguous, unreadable, or malformed member. An empty snapshot is valid and can represent every member being added or removed.

**Acceptance fixture.** `order.json` and `invoice.json` both reference the canonical ID of `money.json`. Only `Money.properties.currency.minLength` changes, from `2` to `3`. All five commands must expose one breaking definition edit. The graph must contain both incoming edges, and selection from either use must open the modified money file. The flat report must identify Money at `$.properties.currency.minLength`. Reverse the edit to verify widening. Remove a member to verify original-side navigation.

Add a counterexample with identical edits at the same path, line, and column in two independent resources. Expect two changes, two hashes, and two selectable files. Also cover a stable-ID move and edit, an anonymous resource, a duplicate ID, a nested relative ID, a retargeted reference, a recursive reference, and shuffled enumeration order. A shared-reference fan-out benchmark must observe one comparison of the target pair and one source body per file and side as the number of incoming edges grows.

## Integration and validation

Use a clean worktree and a fresh, nontracking branch in each changed repository. For each milestone, integrate libopenapi into Doctor, then consume Doctor and Cowboy in the CLI. Develop with a local Go workspace and a local Cowboy package build. Pin published module and npm versions in the consuming changes. Rebuild both CLI bundles from the lockfile. Keep each tested change in a focused commit and record the selected versions and benchmark results with the integration change.

- In libopenapi run `go test ./datamodel/... ./index ./what-changed/...`. In Doctor run `go test ./model/... ./changerator/...`. Run `go test ./what-changed/...` in libasyncapi with the integration pins. Include focused race tests for shared references and policy isolation.
- In Cowboy run `npm test` and `npm run build`. In the CLI report UI run `npm ci`, `npm run typecheck`, `npm test`, and `npm run build`. Verify the released public examples in the Hugo site build.
- In the CLI run `go test ./cmd -count=1` and `go test ./... -count=1`, with focused race checks on history release. Verify help and Petstore through the existing commands, then run the AsyncAPI reports, graph, and history fixtures. Compare `BenchmarkOpenAPIReport` and `BenchmarkAsyncAPIReport` with `-benchmem` on the same toolchain.

At the target CLI revision the executable Petstore test expects **45 total and 19 breaking**. The older checkout instructions quote 42 and 18. Use the tested target as the comparison baseline.
